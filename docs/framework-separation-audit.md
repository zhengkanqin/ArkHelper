# ArkFramework 关联与功能边界

审计日期：2026-11-09；目标版本：ArkHelper 1.0.0。

## 当前结论

- ArkHelper 从自身目录构建和运行，不依赖外部 ArkFramework 项目、DLL 或独立插件。
- 原生加载、Hook 生命周期、任务调度、IL2CPP 封装及伤害统计仍有上游源码继承，来源与 GPL 义务必须保留。
- 当前业务代码未发现修改生命、伤害、费用、资源、结算、自选干员、自定义关卡/藏品、绕过条件选关等功能。此结论限于已检查的源码，不为其他同名版本背书。
- 当前仍通过 DLL 注入和原生 Hook 采集数据。它不是完全只读的进程访问，也不表示获得官方认可或没有账号风险。

## 检查范围

检查 `src/`、`native/`、`include/` 及构建、启动、IPC 与打包入口；只读比对用户提供的上游源码快照。结合调用点与执行流程检查，区分游戏原函数的观察回调、助手自身状态写入、注入参数写入和游戏玩法数据写入。

文件映射工具可重新运行：

```powershell
python tools/audit_framework_lineage.py --reference <上游源码目录> --output build/framework-lineage.json
```

映射只比较生产代码/头文件及已知重命名，忽略换行差异；它不代表语义相似度或版权贡献比例。本机档案、构建输出及测试夹具不属于产品功能。

## 已删除的遗留

- 未使用的托管字段写入、对象/数组构造与泛型构造接口及导出绑定。
- 旧游戏内界面的 Unity 输入拦截与窗口布局代码。
- 正式运行时的外部 DLL 扫描、加载、热重载和外部控制入口。相关生命周期测试采用独立对象文件和测试宏，避免混入产品。
- 旧独立设置窗口、重复 PRTS 网络客户端、离线关卡包加载器、旧界面状态与 ImGui 依赖。

正式产品只注册静态内置模块；空注册表也拒绝外部模块，输入适配器为空。保留的内部模块契约不意味着允许加载外部游戏插件。

## 仍保留的机制

| 入口 | 用途与边界 |
| --- | --- |
| native/loader/remote_thread_loader.cpp | 远程线程加载私有运行时；写入加载参数与启动代码 |
| native/loader/window_hook_loader.cpp、native/bootstrap/message_hook.c | 窗口消息 Hook 加载同一私有运行时 |
| native/core/native_hook*.cpp、MinHook | 修改函数入口建立跳板，观察采集回调并安全排空 |
| native/modules/damage_meter/native_capture.cpp | 转发原参数和返回值，观察战斗生命周期、伤害、治疗与费用 |
| native/modules/provider/capture/ | 读取当前实例、剩余路径、范围和坐标；无法确认的字段标为不可用 |

`ModifyCost`、`Withdraw`、`StartGame` 等采集入口在游戏本来调用时执行观察，不由助手主动加费、撤退或选关。暂停与倍速读取 getter，不调用设置器。IPC 提供显示开关、查询与具体实例路径请求，没有通用字段写入、执行脚本或任意选关命令。

完全取消注入/Hook 需要改用进程外数据来源，并重新评估精确统计和路径的可获取性；当前版本没有完成这种机制替换。

## 首次使用

风险窗展示项目理念、技术方式及崩溃、兼容、性能、账号处罚风险。须连续前台阅读超过 10 秒，再主动勾选并确认；确认前不发布游戏连接标记，不打开覆盖层，不自动启动游戏。版本化记录只保存在本机，保存失败不放行。不同意或关闭即退出。

自动交互验证只操作 `build/portable-check/` 下的解压副本，不替真实安装用户确认。
